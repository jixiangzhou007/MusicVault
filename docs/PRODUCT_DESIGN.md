## 1. 设计意图

给自己和朋友用。不是再做一个网易云/QQ 音乐官方客户端，而是用**一个播放器**同时管好自己的文件，并听散落在各个平台上的歌。

两个并列的核心问题（同等重要，不是「本地为主、在线为辅」）：

**核心 A · 本地听与管**  
硬盘或 NAS 上的歌要能播、能管：标签、整理、歌词、歌单。远程文件夹（NAS / WebDAV）属于这条，不是边角功能。

**核心 B · 跨平台在线听**  
喜欢的歌和**歌单**散在网易云、QQ 等 App 里，不想切软件。用非官方 API 收到同一播放器：**搜索、导入歌单、在线播放**是必须打通的。  
**下载不合规，定位为尽力而为**：Windows 上能下最好；macOS 下不了只保证在线听，不算产品失败。不承诺替代会员，接口随时可能听不了。

围着两核转的能力：发现（逛/搜）、识曲、同一底栏播放、平台歌单导入；下载任务是尽力路径，不是核心承诺。

给朋友用时仍然成立：

1. 解压即用，不读 README、不配环境变量、不自己编译。
2. 第一次成功二选一：已有文件（含稍后加 NAS）就播；没有文件就去发现里听、或导入平台歌单。
3. 第一版：**Windows x64** — A 完整，B 能搜能听能导歌单，下载能用最好。**macOS Apple Silicon** — A 能播，B **以在线播放 + 歌单导入为准**，下载不是合格线。不做 iOS、不做 32 位 x86。
4. 能力不够必须说清。下载不可用时禁用并说明，不要假装能下。

口号「下载即整理，整理即播放」描述的是**下载成功之后**如何进入核心 A；核心 B 的口号是：**一个播放器，听多个平台。**

## 2. 产品定义

| 维度 | 定义 |
|------|------|
| 品类 | 个人音乐桌面应用：本地库管理 + 多平台在线听 |
| 形态 | Avalonia 11 + .NET 8 单窗口；底栏播放器同时服务本地与在线 |
| 闭环 A | 文件夹 / NAS / WebDAV → 索引 → 标签与整理 → 本地播放与歌词 |
| 闭环 B | 搜/逛/识曲或**导入平台歌单** → 在线播放（同一底栏）；下载仅尽力而为 |
| 不提供 | 官方授权、会员替代、把下载写成可承诺能力 |
| 开源许可 | MIT；用户数据默认仅本机 |

两核 + 轨道（叙事上两核并列，实现上在一个应用里）：

| | 内容 | 对朋友 |
|--|------|--------|
| **A 本地** | 扫描、多库、标签、整理、歌词、自建歌单、NAS/WebDAV | 必须能加文件夹并出声 |
| **B 在线** | 多平台搜、**导入平台歌单**、在线听 | 必须能听、能导歌单；下载能用最好，Mac 可不下 |
| **轨道** | 发现精选、识曲、传输队列、百科/指纹 | 传输随下载降权 |

## 3. 用户与任务

### 3.1 用户

| 角色 | 是谁 | 成功标准 |
|------|------|----------|
| 首要 | 自己和朋友：Windows x64 或 Mac M 系列 | 本地能播能管；在线能在一个窗口里听不同平台的歌 |
| 支持成本 | 朋友会解压、不会配 API | 捆绑 API 的 Windows 包必须静默可用 |
| 非用户 | iPhone/iPad、第一版 Intel Mac、要官方正版会员替代保证的人 | 不承诺 |

### 3.2 任务分层

| 优先级 | 任务 | 对应核 |
|--------|------|--------|
| P0 | 加本地文件夹（或 NAS）并播放、看歌词 | A |
| P0 | 搜到歌或打开导入的平台歌单，**在线播放** | B |
| P0 | 粘贴网易云 / QQ 等链接，导入歌单后可听 | B |
| P1 | 标签、整理流水线、去重、自建歌单、M3U | A |
| P1 | 多平台源切换、听失败时的原因 | B |
| P2 | 下载入库（Windows 尽力；Mac 不做合格线） | 尽力 |
| P2 | 发现逛精选、识曲 | B 轨道 |
| P2 | 备份、主题语言、百科、AcoustID | 增强 |

## 4. 设计原则

1. **双核并列**：新功能必须服务「本地听与管」或「跨平台在线听 / 导歌单」。NAS 算核心 A。下载不算核心承诺。
2. **同一条播放栏**：本地文件、NAS 缓存、在线试听都走底栏，用户不要为换平台而换窗口。
3. **听是必须，下是尽力**：核心 B 的成功是出声。下载不合规，能用最好；不能用就禁用并说明，尤其 macOS 只保证在线播放。
4. **诚实**：接口不是官方会员。听不了要点名原因。禁止把下载写成卖点或保证。
5. **一个播放器听多个平台**：已接的网易云、QQ 等源和歌单导入是核心 B，不从默认体验藏掉。90 天不扩新平台，把能听和能导歌单做稳。
6. **语义 Token，禁止页面魔法数**：见设计系统。
7. **反馈分层**：Message / Alert / Empty / Modal / Drawer，禁止混用。
8. **可点即可用**：无能力则禁用并说明。
9. **中英同步**：菜单名词、按钮动词。
10. **安全默认**：整理仅已选；去重默认只删索引；批量下载先确认。
11. **少即是多**：90 天不扩新平台、不扩新远程协议、不重做识曲交互、不宣称 iOS。已有平台以「能听」为优先，而不是再加源。

## 5. 边界与非目标

### 5.1 明确不做

- iOS / Android / Linux 发行版
- Windows 32 位（x86）、Windows ARM（第一版）
- macOS Intel 作为第一版安装包（脚本可编，不作为朋友资产）
- 官方音乐平台合作或内置正版流媒体
- 云同步、多端账号、社交、歌词社区
- 作者托管的公共搜索 API（朋友全员依赖你的服务器）
- 遥测、广告、用户行为上报
- 大范围换肤引擎、第二套设计系统

### 5.2 合规姿态

- 软件不提供正版曲库，也不替代平台会员合同。
- 非官方接口未经平台授权，能听能下取决于接口是否返回地址；随时会断。
- **下载功能不合规**：产品不把它当作可承诺能力。Windows 保留尽力实现；macOS 下不了只保证在线播放。对外不宣传「免会员下载」。
- 首次启动保留版权声明。用户自行判断所在地法律与平台协议。

## 6. 信息架构

### 6.1 应用壳（现行 = 目标）

单窗口。顶栏一级导航 + 条件二级浏览条 + 主区 + 右侧栏（歌词/元数据/队列）+ 底栏播放器。

```
┌ 顶栏：首页 | 曲库 | 发现 | 整理工具 | 设置     下载任务图标 / 健康点 / 窗口控件 ┐
├ 曲库二级（仅曲库）：歌曲 | 艺术家 | 专辑 | 歌单                         ┤
├ 主区                                                              ┤
├ 右栏（按需）：歌词 / 元数据 / 播放队列                                ┤
└ 底栏播放器：封面 曲目 传输键 进度 音量 队列 歌词 均衡器 全屏/精简        ┘
```

| 顶栏 | 枚举 | 职责 |
|------|------|------|
| 首页 | `Home` | 正在播放氛围、最近 / 常听 / 推荐；空态引导 |
| 曲库 | `AllTracks`（组） | 本地收藏浏览；二级切歌曲/艺术家/专辑/歌单 |
| 发现 | `Search` | 跨平台逛/搜/**在线听**/入队下载；识曲入口 |
| 整理工具 | `AudioTools` | 载入队列 → 底栏刮削为主；重命名/去重在「更多」 |
| 设置 | `Settings` | 外观、播放、下载、数据、在线源、更新 |

**不在顶栏文字 Tab、但必须可发现：**

- **库来源**（`Libraries`）：本地文件夹、NAS、WebDAV。这是「本地盘从哪来」，不是高级插件。入口：空态、曲库页、设置数据/概览、命令面板。
- **下载任务**（`Downloads`）：队列 / 失败 / 历史。入口：右上角图标（进行中或失败时角标）、发现侧栏、命令面板；空首页仅在有待处理任务时出现。成功并已整理刮削的歌在曲库里听，历史不是第二套曲库。
- **关于**：设置概览内 + 顶栏关于命令。

旧文档 `menu-ia-v1` 把「最近播放」写作曲库二级，**作废**。最近播放在首页。

### 6.2 设置（现行）

左侧 7 项（代码 `SettingsSectionKind`）：

| 导航 | 职责 |
|------|------|
| 概览 | 关于为主（身份 / 能力说明 / 开源）+ 轻量快捷入口；曲库 KPI 在「数据」 |
| 外观 | 主题、字号、强调色、语言 |
| 播放与音频 | Tab：播放 · 歌词与音效 · 快捷键 |
| 下载与缓存 | 目录、音质、NAS/WebDAV 缓存 |
| 数据 | 备份与恢复 |
| 在线源 | API、登录、探针、识曲（枚举名仍为 `Advanced`） |
| 更新与诊断 | 应用更新、内置 API、更新记录、故障排查 |

保存规则（现行）：偏好字段**自动保存**——开关/下拉等即时写入；URL、路径、Cookie、密钥等文本约 400ms 防抖，切分区 / 离开设置 / 退出前强制冲刷。备份、探针、登录、更新安装等**操作**仍用按钮与确认。禁止再引入「改完要点保存」第三种规则；新偏好字段必须标为即时或防抖。详见 [2026-08-20-settings-autosave-design.md](superpowers/specs/2026-08-20-settings-autosave-design.md)。

设置导航收到 4 项**不在**本阶段；与自动保存解耦。

### 6.3 命令面板

快速跳转页面与高频动作。`Nav.Library` 指向库来源页，顶栏「曲库」指向歌曲列表。两者名称不同，保持。

## 7. 核心旅程

### 7.1 启动（现行）

1. 主窗口显示。
2. 未同意版权 → 版权对话框；拒绝则退出。
3. 未完成向导且曲库为空 → 首次向导；已有库则跳过向导。
4. 后台：扫描、API 自启、更新检查等。

### 7.2 首次向导

**现行（批次 1 已落地）：** 欢迎 → 选路（我已有歌曲 | 在线听 / 找歌）→ 路径详情。下载目录静默创建，不再作为独立步骤。

```
欢迎 → 选路（我已有歌曲 | 在线听 / 找歌）→ 只问这条路需要的东西 → 开始
```

| 选择 | 存盘 `FirstRunOnboardingPath` | 第 3 步 | 静默完成 |
|------|-------------------------------|---------|----------|
| 我已有歌曲 | `LocalLibrary` | 选文件夹；可提示稍后可加 NAS | 下载目录用默认 |
| 在线听 / 找歌 | `Discover` | Windows 有 `api/`：可搜索、试听、导歌单，静默开捆绑 API；Mac：以在线听和导歌单为准，下载能用则保留、不作保证 | 下载目录仍默默创建，不提问 |
| 跳过整段向导 | `Unset` | — | 完成标记仍写入 |

对话框宽度保持现有 520–600。选路为竖排两张卡片，选中态用 `AccentSoft`。不出现 `go-music-api.exe` 等实现名。

细节与测试见 [superpowers/specs/2026-08-14-friend-ready-public-product-design.md](superpowers/specs/2026-08-14-friend-ready-public-product-design.md)。

### 7.3 空首页主按钮（目标）

| 路径 | 已有音乐库 | 主按钮 |
|------|------------|--------|
| `LocalLibrary` | 否 | 添加音乐文件夹 |
| `LocalLibrary` | 是 | 查看曲库 |
| `Discover` | 任意 | 去发现 |
| `Unset` | 否 | 两个对等入口：添加音乐文件夹、去发现 |
| `Unset` | 是 | 查看曲库；次要「去发现」 |

次要入口仍保留库来源（含 NAS）/ 下载任务（仅有待处理任务时）/ 设置。空首页主按钮按上表分流；跳过向导时两核入口对等。

### 7.4 发现与平台歌单（核心 B）

**听：** 发现页为深色乐馆壳：常驻细搜条；无搜索会话时：广告轮播 + 为你精选多列（悬停翻页/收藏）；浏览中枢无页面滚动。提交搜索后同一细条下出结果。识曲 / 粘贴在「更多」或快捷入口。均 → 同一底栏在线播放。识曲成功后可点「播放」或「下一首播放」，仍留在发现；双击结果行同样可听。无可播放源时按钮禁用，并提示改关键词搜索。统一源失败条以搜索结果态为主。这是核心 B 的合格线。

**导歌单：** 在歌单页粘贴网易云、QQ 等**歌单链接** → 解析曲目列表 → **不经下载即可在线逐首播放**。批量下载仍可用，但是次要操作。

**下（尽力）：** 统一 API 已配置时保留下载（含 Mac）。仅接口未配置或不可用时禁用入口：Mac 提示「本机以在线播放为准」，Windows 提示去配置 API。失败不算发版失败。NAS / WebDAV 整库下载属核心 A，不受此门禁。

已接平台不要从默认体验藏掉。90 天不扩新平台。

### 7.5 播放（现行）

本地文件、NAS 缓存、在线试听共用底栏。Windows：NAudio，可选 LibVLC。macOS：包内必须有 `libMusicVaultPlayer.dylib`。均衡器在引擎不支持时禁用。

全屏：单击播放栏封面进入；双击标题区进精简窗。封面与歌词大于工具控件。

### 7.6 整理（现行 = 目标）

不是四个独立页，而是一条流水线，队列始终在：

1. 选曲（载入工作集）
2. 补标签（刮削 / 查找替换）
3. 整理文件（模板预览后执行）
4. 去重（默认只删索引）

作用范围默认「仅已选」。从歌曲页可将勾选曲目并入整理队列。

### 7.7 远程库（核心 A 的盘，不是第三产品）

库来源页 → 添加 NAS 或 WebDAV → 测连 → 扫描 → 播放走缓存。不单独占顶栏，但空态/曲库必须能走到。见 [NAS_LIBRARY.md](NAS_LIBRARY.md)。

## 9. 视觉与交互

细节与 Token 表见 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)。Ant 结构分层见 [DESIGN-SYSTEM-ANT.md](DESIGN-SYSTEM-ANT.md)。本文只锁产品层规则。

### 9.1 气质

深色为专业默认；浅色完整可用。默认强调色 `#007AFF`。控件圆角 4px（`RadiusControl`）。内容区安静，强调色只用于选中、主按钮、进度、链接。

灵感来自播放器的「打开就听」，不是后台管理台。工具（筛选、平台、探针）默认收起。

### 9.2 硬约束

- 禁止 View 层硬编码 `#` 色（豁免表见设计系统）。
- 禁止字面量 `FontSize` / 随意 `Margin`（审计脚本门禁）。
- 同一类控件同一套 class（如 `row-action-btn` + `icon-sm`）。
- 浅强调底上的字必须用 `OnAccentSoftForegroundBrush`，禁止蓝底蓝字。
- 发布走 `audit-design-system.ps1 -FailOnViolation`。

### 9.3 空态与加载

- 空数据：`EmptyStateView`，一句原因 + 一个主 CTA。
- 列表首屏：Skeleton，不用整页转圈挡住壳。
- 分区失败：分区内重试，不整页红条。

### 9.4 模态

应用内 `AppModal`（主窗口上的卡片），不要随便新开系统窗口。宽表单用 Drawer。不可逆操作用明确文案的确认框。

以 [platform-capability-matrix.md](execution/platform-capability-matrix.md) 与 [phase-4-capability-guardrails.md](execution/phase-4-capability-guardrails.md) 为验收基线。

| 模块 | Windows x64 | macOS Apple Silicon |

## 11. 数据、隐私、架构（产品相关）

### 11.1 数据位置

- Windows：`%LOCALAPPDATA%\MusicVault\`
- macOS：`~/Library/Application Support/MusicVault/`

含 `musicvault.db`、下载目录、`backups/`、`settings.json`。Cookie / 凭据仅本机；NAS 密码走 DPAPI（Windows）。无内置遥测。

主要实体见 [DATA_MODEL.md](DATA_MODEL.md)：Tracks、Libraries、Playlists、PlayHistory、DownloadHistory、ArtistProfiles。用户偏好在 `settings.json`；库 schema 版本在 SQLite。

**现行字段：** `FirstRunOnboardingPath` = `Unset | LocalLibrary | Discover`。旧版缺省 = `Unset`。

### 11.2 代码分层（不可倒依赖）

```
App（UI / VM）→ Services（业务 / Features / 播放 / 平台）→ Data / Core
Core 无 I/O
```

新业务流程进 `MusicVault.Services/Features/`，不要在巨型 ViewModel 里再堆一套。公开产品第一批允许改向导与首页 VM，不要求趁机拆完 Search/Settings。

## 12. 分发

### 12.1 朋友资产（目标）

只承认两个文件名：

| 资产 | 系统 | 必须包含 |
|------|------|----------|
| `MusicVault-X.Y.Z-win-x64.zip` | Windows 10/11 x64 | `MusicVault.exe` + `api/` |
| `MusicVault-X.Y.Z-osx-arm64.zip` | macOS 12+ Apple Silicon | 可执行文件 + `libMusicVaultPlayer.dylib` |

不要：万能包、iOS、win-x86、第一版 osx-x64。

Windows 另有 Velopack `Setup.exe`：仅安装版可应用内更新；便携 zip 不能走 Velopack。两条线不要混，见 [ONLINE_UPDATE.md](ONLINE_UPDATE.md)、[DISTRIBUTION.md](DISTRIBUTION.md)。

Mac 未签名时，Release 说明写三行：下 arm64 包；无法打开则右键打开；Intel Mac 暂不支持。第一版不做 Apple 公证。

### 12.2 产出顺序

1. 向导 + 空首页落地后，打 Windows 包即可发给 Windows 朋友。
2. Mac 包需要 macOS runner 或真机执行 `publish-macos.sh osx-arm64`。没有产物时**只发 Windows**，不挡 Windows 朋友。
3. CI `macos-latest` 无 VLC.app 时，不以 LibVLC 为硬门槛，以 dylib 为准。

## 13. 质量门槛

每次声称「可发给朋友」之前：

1. `dotnet build` / `dotnet test` Release 通过。
2. `dotnet format --verify-no-changes`。
3. `audit-design-system.ps1 -FailOnViolation`。
4. Headless：`scripts/smoke-ui-headless.ps1`（导航 + 设置本地化）。
5. Windows：用 `publish-with-api.ps1` 产物做 [TESTING.md](../TESTING.md) P0（启动、出声、版权、向导双路径）。
6. 文案：README / GitHub Release / 关于页与第 10 节能力表一致。

不要求：全量 UI 自动化、Mac 无真机时的听感测试（有真机则勾播放 P0）。
