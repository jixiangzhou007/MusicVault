# 整理工具页 · 产品重设计（v2）

> **2026-11-12：** 完整四步流水线延后。现行实现以  
> `docs/superpowers/specs/2026-11-12-organize-scrape-first-design.md` 为准（刮削优先 + 底栏）。

## 1. 用户与场景

| 用户 | 目标 |
|------|------|
| 入库后整理 | 批量补标签、统一文件夹结构 |
| 曲库维护 | 批量改字段、去重、删冗余索引 |
| 从浏览页过来 | 在「全部歌曲」勾选一批歌，到整理页继续处理 |

**核心心智：不是四个独立页面，而是一条流水线——先有一批「待整理曲目」，再选操作。**

## 2. 设计原则

1. **队列优先**：整理队列（曲目表）始终占主区域，切换操作时不消失。
2. **一步一栏**：顶栏只保留应用级导航「整理工具」；步骤切换在页面内完成，不与壳层 Tab 重复。
3. **操作就近**：补标签 / 整理 / 去重 的控制放在**底部工具条**，避免右侧窄栏挤压列表。
4. **与曲库一致**：载入区（音乐库 + 筛选 + 载入）紧贴列表上方，交互对齐「全部歌曲」。
5. **安全默认**：作用范围默认「仅已选」；整清单操作二次确认；去重默认仅删索引。

## 3. 信息架构

```
整理工具（单页）
├── ① 选曲      … 载入 / 勾选 / 看清单与处理状态列
├── ② 补标签    … 刮削 + 查找替换（作用范围）
├── ③ 整理文件  … 路径模板 + 预览 + 执行
└── ④ 去重      … 扫描 + 移除重复（默认仅索引）
```

## 4. 布局线框

```
┌──────────────────────────────────────────────────────────────┐
│ [选曲] [补标签] [整理文件] [去重]          作用范围: 仅已选|整清单 │  ← 步骤条 + 范围（有队列时）
│ 一句话说明当前步骤要做什么                                      │
├──────────────────────────────────────────────────────────────┤
│ 音乐库 ▼  歌手…  歌名…  [载入到整理队列]   共 N 首 · 已选 M    │
├──────────────────────────────────────────────────────────────┤
│ # 选 歌曲 艺术家 专辑 年份 标签 封面 歌词 操作                  │
│──────────────────────────────────────────────────────────────│
│                     （整理队列 · 全宽列表）                      │
├──────────────────────────────────────────────────────────────┤
│ 操作工具条（仅 ②③④，在表头上方）：查找替换 / 刮削 / 整理 / 去重   │
│──────────────────────────────────────────────────────────────│
│                     （整理队列 · 全宽列表）                      │
└──────────────────────────────────────────────────────────────┘
```

## 5. 关键交互

| 动作 | 行为 |
|------|------|
| 进入整理工具 | 队列为空；空状态引导「选音乐库 → 载入」或去全部歌曲加入 |
| 切换步骤 | 列表不变；底部工具条切换内容；无队列时工具条禁用并提示先载入 |
| 载入 | 不随切库自动载入；用户点「载入到整理队列」 |
| 从全部歌曲加入 | 合并进队列，摘要显示来源 |
| 作用范围 | ②③④ 显示；默认仅已选 |

## 6. 非目标（本期不做）

- 自动载入整库
- 多队列 / 保存队列方案
- 向导蒙层、步骤强制锁定

## 7. 验收标准

1. 壳层二级 Tab（工作清单/补标签…）不再显示。
2. 页面内步骤条可切换，列表始终可见且可滚动。
3. 选曲步骤下列表全宽；②③④ 底部出现工具条。
4. 空状态、载入中、有数据三态清晰。
5. 原有批量能力（刮削、替换、整理预览、去重）均可从对应步骤触达。
