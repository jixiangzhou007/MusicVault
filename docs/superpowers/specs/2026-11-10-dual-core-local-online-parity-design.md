# 双核对等：本地库像库 + 在线听像壳（设计）

日期：2026-11-10  
状态：已确认（用户选交付路径 **甲**：切片 1→2→3→4，每片可发布）  
对照：`PRODUCT_DESIGN.md` 双核定义；竞品调研（QQ / 网易云 / 酷我 / 汽水 PC）；现行发现 / 曲库 / 识曲 / 库来源实现

## 1. 意图

MusicVault 的特色是**同一播放器里本地与在线都硬**，不是偏科流媒体，也不是只做本地播放器。

本轮目标：用四个可感知切片，把「本地像专业库、在线像干净听歌壳」做到朋友不用你教学也能感到双核对等。

对外标尺不变：

- 核 A：文件夹 / NAS → 索引 → 能找、能筛、能播、能看缺什么  
- 核 B：搜 / 逛 / 识曲 / 导歌单 → **同一底栏出声**；失败诚实；下载仍尽力而为  

## 2. 不做

- 新音乐平台、新远程协议  
- 识曲交互重写（入口仍在发现；只做结果→队列闭环）  
- 皮肤商城、播放器黑胶皮肤、桌面动态主题、AI 伴听 / Agent  
- 会员弹窗、看广告听歌、社交乐评 / 一起听  
- 设置导航收到 4 项、拆分巨型 ViewModel（除非切片内局部必要）  
- 改变即时/自动保存合同（已落地）  

可选加码（**不进甲默认四片**）：侧栏可收起——用户点名再开。

## 3. 交付路径（甲）

每片独立可测、可发布（`publish-with-api.ps1 -Restart`）。顺序固定，保证双核交替可见：

| 序 | 核 | 切片名 | 一句话成功 |
|----|----|--------|------------|
| 1 | A | 本地按文件夹浏览 | 加完库后能按磁盘目录找到歌 |
| 2 | B | 发现主入口 + 统一失败 | 打开发现知道先点哪；挂了有下一步 |
| 3 | A | 曲库筛选 + 缺项标记 | 千首歌不用搜也能收窄；缺封面/歌词一眼可见 |
| 4 | B | 识曲结果入队 / 下一首 | 识完直接进底栏，不绕搜索重放 |

## 4. 切片 1 · 本地按文件夹浏览（核 A）

### 4.1 用户故事

朋友加了 `D:\Music\流行` 与 `D:\Music\古典`（或 NAS 下两层目录）后，希望像资源管理器一样按文件夹点进去听，而不是只在「全部歌曲」里搜文件名。

### 4.2 产品行为

- 在曲库相关浏览中增加 **「文件夹」维**（具体入口：歌曲页工具条或库来源旁的浏览模式切换——实现计划选定，须与现有艺术家/专辑并列，不新占顶栏一级导航）。  
- 树或列表展示：库根 → 相对路径文件夹 → 该文件夹下曲目（可含直接子文件；是否递归由实现计划定默认，推荐「当前文件夹非递归 + 可进入子文件夹」）。  
- 显示路径时对 NAS/WebDAV 用现有库名 + 相对路径，不暴露吓人的 UNC 除非用户需要。  
- 空文件夹：短文案 + 「去库来源」或「扫描」。  

### 4.3 非目标

- 不在本片做标签批量刮削、不改整理流水线。  
- 不新增「资源管理器」独立顶栏项。  

### 4.4 验收

1. 至少两个本地子文件夹有歌时，能分别进入并只看到该夹内曲目。  
2. 双击仍走同一底栏播放。  
3. 无库时引导添加文件夹，不白屏。  

## 5. 切片 2 · 发现主入口 + 统一失败（核 B）

### 5.1 用户故事

打开「发现」时，朋友应感到「今天先听什么」，而不是「先配哪个源」。源挂了要看得见、有下一步。

### 5.2 产品行为

**日常层（默认可见）**

1. **一个主 CTA 区**（三选一内容，按数据有无降级，不必三个按钮并列抢视线）：  
   - 有最近在线/本地播放 → 「续听」或「继续听类似」  
   - 否则 → 「随便听听 / 精选」进入现有逛精选  
   - 再否则 → 「去搜索」聚焦搜索框  
2. **统一失败条**（源级）：点名失败源 + 短原因 + 「重试」+ 「去在线源设置」（沿用现有能力芯片/探针，统一视觉与文案合同）。  
3. 搜索、平台歌单粘贴、识曲入口保留，但视觉层级低于主 CTA（次要）。  

**不做**

- 不上大模型「场景模式」；场景用现有最近播放 / 精选拼。  
- 不把平台矩阵默认全部展开。  

### 5.3 验收

1. 冷启动进发现：首屏有且仅强调一个主行动。  
2. 人为断一个源：失败条出现且能进设置。  
3. 顶栏导航项数量不变。  

## 6. 切片 3 · 曲库筛选 + 缺项标记（核 A）

### 6.1 用户故事

曲库上千首时，想快速只看「缺封面」「缺歌词」或某音质，方便补全或整理，不必记歌名。

### 6.2 产品行为

- 歌曲列表（及文件夹维下列表若已存在）提供 **可清除的筛选条**：至少支持  
  - 缺封面  
  - 缺歌词（无关联 LRC / 内嵌歌词按现行数据模型定义）  
  - 可选：音质档（若元数据已有）或「仅本地 / 仅缓存」若模型允许且成本低  
- 行内轻量标记（图标或次要字色）：缺封面 / 缺歌词，不抢播放主操作。  
- 筛选状态离开页可丢弃；不必持久化（实现可选择会话级记忆，非必须）。  

### 6.3 非目标

- 不做复杂流派 AI 分类。  
- 不做 QQ 式「曲风」云标签依赖。  

### 6.4 验收

1. 勾选「缺封面」后列表只含缺封面曲目；清除后恢复。  
2. 标记与筛选语义一致。  
3. 大库（建议测试 ≥1k 行）筛选不卡死 UI（异步或索引策略在计划中写明）。  

## 7. 切片 4 · 识曲结果入队 / 下一首（核 B）

### 7.1 用户故事

用发现里的识曲认出一首歌后，希望马上在底栏听或插到下一首，而不是只把歌名填进搜索再手动点。

### 7.2 产品行为

- 识曲成功结果卡增加主操作：**播放**（立即）与次要：**下一首播放** / **加入队列**（与现有在线结果入队语义对齐）。  
- 能解析到可播在线源时走在线预览队列；仅本地匹配时走本地。  
- 失败：保留现有错误文案；不发明新识曲 UI。  
- **不**改麦克风/文件选择流程（冻结「识曲交互重写」）。  

### 7.3 验收

1. 成功识曲后一点「播放」→ 底栏出声且不强制跳转离开发现（或跳转后仍可回，以现有导航习惯为准，计划写死一种）。  
2. 「下一首」在当前曲目结束后切入。  
3. 无可用播放源时按钮禁用并短说明。  

## 8. 跨切片原则

1. **同一底栏**：本地文件夹曲与在线识曲结果不得开第二套播放窗。  
2. **能力不够就禁用说明**：下载、某源、识曲无匹配——禁用 + 一句人话。  
3. **少即是多**：每个切片只加一个主任务；工具默认收起。  
4. **双核叙事**：发布说明 / 概览文案若改动，须同时提本地与在线，避免「又变成下载器」或「又变成网易云皮」。  

## 9. 文档

实现完成后回写 `PRODUCT_DESIGN.md`：

- 能力矩阵：文件夹浏览、曲库缺项筛选、发现主 CTA、识曲入队标为现行。  
- 不改冻结表（识曲交互重写仍冻）。  

## 10. 风险

| 风险 | 缓解 |
|------|------|
| 文件夹树在超大库上慢 | 懒加载子夹；默认非递归列出 |
| 发现主 CTA 与现有精选/搜索抢视线 | 视觉合同：一块主按钮 + 其余次要 |
| 缺歌词定义不一致 | 计划中写死判定函数并单测 |
| 识曲有结果无可播 URL | 禁用播放并引导搜索同名 |
