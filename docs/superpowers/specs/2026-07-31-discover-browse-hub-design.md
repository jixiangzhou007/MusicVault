# 发现页产品化：浏览中枢（方案 A）

日期：2026-07-31  
状态：已实现（2026-07-31）  
前置：UI P0 沉浸 polish（`2026-07-29-ui-p0-immersive-polish-design.md`）已落地  

**相对 P0 的变更**：P0 发现验收为「首屏以结果区为主、搜索带一行」。本期在**无已提交搜索**时改为「首屏为精选浏览」；有搜索后仍以结果区为主。传输侧栏与「更多」收敛规则继承 P0。

## 目标

把发现页从「搜索工具台」拉成「可逛 + 可搜」的产品首页，并与首页空态 / 播放器气质统一。

对齐用户痛点：

1. **工具台感** — 顶栏控件抢戏、像后台  
2. **搜前不可逛** — 无有效搜索时缺少内容  
3. **气质不统一** — 与首页 / 播放器不像同一产品  

## 方案摘要

**浏览中枢（A）+ 混合空态（搜前精选 / 搜后结果）+ 搜索形态 C（居中大搜索 → 吸顶细条）**

- 默认展示精选：热门榜单 + 推荐歌单墙  
- 提交搜索后切到结果列表；清空后回到精选  
- 搜索高级能力（模式 / 艺人 / 登录等）仍在「更多」内  
- 圆角与控件形状 **严格沿用现有 token**，不做胶囊大圆角  

## 非目标

- 识曲流程重写  
- 发现信息流 / 个性化推荐算法  
- 改主导航 IA  
- 发现页内嵌完整榜单/歌单详情 UI（详情仍归歌单页）  
- 最近搜索入口（本期未选）  
- 结果与精选双栏并存  

## 信息架构

### 两态

| 状态 | 进入条件 | 主内容 |
|------|----------|--------|
| **浏览态** | 无有效已提交搜索词，或用户清空搜索 | HeroSearch + ChartsRail + PlaylistWall |
| **搜索态** | 用户提交非空搜索（含解析等非空结果流） | CompactSearch（吸顶）+ ResultsList |

传输侧栏：保持 P0 — 默认收起，入队可自动展开。

### 与歌单页职责

| 页面 | 职责 |
|------|------|
| **发现** | 逛（精选入口）+ 搜（在线曲目） |
| **歌单** | 管（自建/收藏）+ 榜单/歌单完整详情与批量操作 |

精选区「全部 / 更多」→ 导航到歌单页对应分区。  
榜单卡 / 歌单卡点击 → 导航到歌单页并选中对应项（复用现有详情，不在发现页复制一套）。

## 组件

### HeroSearch（浏览态）

- 页内偏上、水平居中的搜索壳（输入 + 平台 + 搜索/清除 + 更多）  
- 视觉：轻底、弱边框；**圆角 = 现有 `RadiusLg` / `RadiusOverlay`（8），禁止 pill（≥16 的胶囊）**  
- 「更多」展开：模式切换、艺人、登录带等（与现 P0 高级区同能力）  

### CompactSearch（搜索态）

- 吸顶细条，同一套字段，去掉浏览态的居中大块布局  
- 清除搜索 → 回浏览态并重新展示精选  

### ChartsRail

- 展示当前平台下热门/榜单卡片约 3～6 张  
- 数据：复用现有 BrowseCards / 榜单加载能力（与歌单页同源或共享服务）  
- 区标题 +「全部」链到歌单页榜单分区  
- 加载：分区骨架；失败：分区内重试，不整页红条霸屏  

### PlaylistWall

- 推荐歌单封面网格约 8 张（随宽度自适应列数）  
- 数据：复用现有推荐/浏览歌单接口  
- 「更多」→ 歌单页  
- 点击 → 歌单页打开该歌单  

### ResultsList

- 沿用现有发现在线曲目表（封面行、操作列）  
- 仅搜索态可见；表头进一步弱化（少「数据表」感，仍可用现有列布局）  

## 交互细则

1. **态切换**：以「是否存在已提交的有效查询」为准，而非仅 TextBox 是否为空（避免打字未搜就拆掉精选）。  
2. **平台切换**：浏览态下切换平台 → 刷新 ChartsRail / PlaylistWall。  
3. **非搜索模式**（解析链接等）：进入该模式且需要结果区时走搜索态布局（CompactSearch + 结果/空态），不强制显示精选。  
4. **API 不可用**：沿用现有发现页告警条；精选分区可单独显示失败/重试。  

## 视觉规则

- **统一性优先**：形状、间距、字号走现有 Theme / Spacing / Radius token（`RadiusSm/Md/Lg/Card` 4–8；封面若已用 `RadiusXl=12` 可沿用）。**禁止**为发现页单独引入更大圆角或胶囊搜索条。  
- **氛围**：浏览态顶部极轻径向氛围，与首页空态同族；不用紫霓虹、不用厚抬升搜索带。  
- **层级**：封面与标题主导；工具控件退后。  
- **动效**：态切换短淡入；卡片 hover 轻微即可。  

## 验收标准

1. 打开发现且无已提交搜索：首屏可见居中搜索 + 榜单区 + 歌单墙，而非空白结果表。  
2. 搜索提交后：精选隐藏，吸顶搜索 + 结果列表；清空后精选恢复。  
3. 点击榜单/歌单卡：进入歌单页对应详情/选中态。  
4. 「全部/更多」进入歌单页对应分区。  
5. 搜索壳与卡片圆角与同页其他控件一致，无胶囊大圆角。  
6. 传输侧栏默认收起行为与 P0 一致。  
7. 主导航、识曲、歌单管理流程无回归性破坏。  

## 实现提示（非规范，供计划用）

- 主改 `SearchPageView` / 对应 ViewModel；精选数据优先接现有 `PlaylistsPage` / Discover 已用服务，避免双份缓存逻辑失控。  
- 样式落在现有 Discover 组件样式文件，扩展而非另起主题。  
- 需补：浏览态可见性绑定、精选加载与平台联动、导航到歌单页的参数/命令。
