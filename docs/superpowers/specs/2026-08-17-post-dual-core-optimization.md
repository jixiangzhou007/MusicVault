## 1. 设计意图（审查标尺）

MusicVault 不是再做一个网易云/QQ 客户端，而是**一个播放器**同时回答两件同等重要的事：

- **核 A · 本地听与管：** 硬盘或 NAS/WebDAV 上的歌能播、能管（标签、整理、歌词、自建歌单）。
- **核 B · 跨平台在线听：** 搜索、导入平台歌单、同一底栏出声。下载不合规，定位尽力而为。

朋友路径：解压即用；第一次成功二选一（已有文件就播 / 没有文件就去发现或导歌单）。能力不够必须禁用并说明。

口号「下载即整理，整理即播放」只描述**下载成功之后**如何进入核 A。核 B 的口号应是：**一个播放器，听多个平台。**

## 3. 客观缺口（按维度）

### 3.1 产品叙事与用户感受

对外第一句仍是下载器。`About.Tagline` / README 首行 = 「下载即整理，整理即播放」。空首页标题 = 「开始你的音乐库」（偏核 A）。`Discover.PageHeader` 仍写「下载到本地」，且视图未绑定（死文案）。空页仍构建「在线源 → 下载中心 → 曲库」步骤但 XAML 已不展示。

**感受：** 朋友打开「关于」或 README，会以为产品卖点是免会员下载，与「听是必须」相反。

### 3.2 UI 层级

| 位置 | 问题 |
|------|------|
| 发现结果工具栏 | 「全部加入下载」仍是 `primary` |
| 榜单详情 | 「批量下载」仍是 `primary` |
| 平台歌单详情 | 已正确：播放 primary、下载 flat |
| 顶栏 | 下载中心与发现同级 + 角标（规范允许六项，不建议本波拆顶栏） |
| 空首页次要 | 常显「下载中心」，与「去发现」并排 |

同类「下载」跨页层级不一致。用户会把下载当成主任务。

### 3.3 播放心智（同一底栏）

本地与在线共用 `PlayerBar`，但 `_isOnlinePreview` 时上一首/下一首通常不可用。用户双击发现结果出声后，无法像听歌单一样切下一首。这是核 B 合格线「打开就听」最大的交互缺口。

### 3.4 架构与编码规范

- 巨型 VM：Search 2691、Artists 2228、Settings 合计 3461、Playlists 1938、Downloads 1632、PlayerBar 约 2302。Features 层约 520 行，多数流程仍在 VM。
- `AppServices` 仍是约 50 个属性的服务定位器；仅 Libraries / Equalizer 收窄注入。
- `.editorconfig` 要求 `*.cs` CRLF，大量 ViewModel 为 LF；`dotnet format --verify-no-changes` 易因换行失败（规范 §13 门禁）。
- **规范已冻结**「拆 Search/Settings/Artists」与「设置导航大改」。本波不得单独立项还债。

### 3.5 质量与诚实

- 向导/CTA/下载可用性有单测；**在线试听 → 底栏**、**导入歌单端到端**缺少集成测。
- Mac：代码策略已落地，**实机未验**（启动、dylib 出声、发现试听）。
- PRODUCT §8 仍把「平台歌单导入后在线听」标成「目标」，与代码和 README 矛盾。

### 3.6 明确不优化（冻结）

新平台、识曲交互重写、设置改 4 项 + 全面自动保存、Linux/iOS/Intel Mac 朋友包、把下载写成承诺、为「看起来跨平台」宣称能力对等、单独立项拆巨型 VM。

## 4. 方案比选

| 路径 | 内容 | 收益 | 风险 | 决议 |
|------|------|------|------|------|
| **A 体验对齐** | 口号、按钮降权、预览会话可切歌 | 朋友第一天体感直接变「播放器」 | 低 | **主路径** |
| B 结构还债 | 拆 Search、收窄 AppServices | 长期可维护 | 与冻结冲突、易回归 | 否；改到的文件才抽 Features |
| **C 验证诚实** | Mac 实机、试听/导入测试、换行策略 | 敢说「可发给朋友」 | 依赖真机 | **与 A 并行** |

推荐：**A + C**。B 只作为触达文件时的顺手抽取，不排期。
